# Пользовательские темы дашборда — дизайн

Дата: 2026-09-26
Статус: утверждён к реализации

## Задача

Сейчас в проекте ровно две темы, захардкоженные в JS-массиве, и переключение
сводится к одному булеву флагу `dark`, который включает `body--dark` у Quasar.
Требуется система, в которой тем сколько угодно, они живут в БД, юзер
загружает их файлами `.json`, скачивает обратно файлом и привязывает к
конкретному дашборду.

## 1. Два независимых понятия тем

Тема дашборда и тема интерфейса — разные сущности с разным жизненным циклом.
Их смешение в текущем коде (`theme.dark` → `$q.dark.set()`) — главная причина,
по которой кастомизация невозможна.

| | Тема дашборда | Тема интерфейса (хром) |
|---|---|---|
| Хранилище | таблица `themes` в БД | `localStorage`, ключ `sm-ui-theme` |
| Что красит | окно дашборда, виджеты, заголовки, границы, тени, шрифты виджетов | диалоги, q-select, кнопки, тулбары, спиннеры, оверлеи |
| Область действия | один дашборд | вся страница |
| Влияет на `$q.dark` | **нет** | **да, единолично** |

Допустимые значения UI-темы: `light` \| `dark` \| `system`. При `system`
значение резолвится в `prefers-color-scheme`; Quasar слушает медиазапрос сам
при `$q.dark.set('auto')`. Переключатель показывает **выбранное** состояние,
а не результат резолва. Ключ в `localStorage` — `sm-ui-theme`.

Следствие: виджеты и страница дашборда **не должны зависеть от `body--dark`**.
На сегодня зависимость ровно в одном месте — `IndexPage.vue:341` использует
`var(--q-card-background)` для фона сетки; заменяется на `--app-bg`. Остальное
уже построено на собственных токенах.

Поле `dark` в теме дашборда **отсутствует**. Оно не участвует в отрисовке
(всё через токены), нужно было бы только для иконки в пикере, а та
вычисляется из яркости `palette.widgetBackground`. Бонус: исчезает возможность
описать в JSON `dark: true` со светлой палитрой и получить тему, которая врёт.

## 2. Формат темы

Значение цвета — union: строка (hex или любой сырой CSS) либо объект-градиент.
Нормализатор приводит к строке CSS.

```json
{
  "id": "midnight",
  "name": "Midnight",
  "version": 1,

  "palette": {
    "appBackground": "#0d1117",
    "appText": "#c9d1d9",
    "widgetBackground": "#161b22",
    "widgetHeaderBackground": {
      "type": "linear",
      "angle": 180,
      "stops": [
        { "color": "#1c2128", "offset": 0 },
        { "color": "#161b22", "offset": 100 }
      ]
    },
    "widgetTitleColor": "#e6edf3",
    "widgetBorderColor": "#30363d",
    "alertColor": "#f85149"
  },

  "border": {
    "width": "1px",
    "style": "solid",
    "radius": "6px"
  },

  "shadow": {
    "widget": { "x": "0", "y": "2px", "blur": "8px", "spread": "0", "color": "#000000", "opacity": 0.4 },
    "text":   { "x": "0", "y": "1px", "blur": "3px", "spread": "0", "color": "#000000", "opacity": 0.6 }
  },

  "font": {
    "family": "Roboto, 'Segoe UI', sans-serif",
    "widgetTitleSize": "14px",
    "widgetTitleWeight": 600,
    "widgetContentSize": "13px",
    "widgetContentWeight": 400
  }
}
```

### 2.1 Полнота темы

**Все поля обязательны, частичных тем не бывает.** Тема — самодостаточный
документ: отсутствие токена означает «автор про него не знал», а не «взять
дефолт». Иначе невозможно понять, является ли расхождение с ожиданием
пользователя ошибкой автора или его замыслом, а `applyTheme` пришлось бы
рассыпаться с фолбэками — ровно та конструкция, которую эта задача убирает.

Значения по умолчанию существуют ровно в двух местах: статические дефолты в
`app.scss` (раздел 4.1) и lenient-режим нормализации для будущего редактора
(раздел 8). В пользовательских темах оба не участвуют.

`version` обязателен и сейчас равен `1`. Миграций между версиями не
предусмотрено (раздел 12).

### 2.2 Тип `Paint`

```
Paint = string | { type: "linear" | "radial", angle?: number, stops: [{ color, offset }] }
```

- Строка — `#rgb`, `#rrggbb` либо готовый CSS (`rgb(...)`, `color-mix(...)`).
  Валидируется на этапе нормализации; нераспознанное в lenient-режиме
  заменяется дефолтом.
- Градиент: `type: "linear"` требует `angle` (градусы), `type: "radial"` —
  `angle` не требуется и игнорируется, если указан. `offset` — целое 0..100.
  Минимум два стопа.

### 2.3 Тип `Shadow`

`{ x, y, blur, spread, color, opacity }`. Собирается в
`{x} {y} {blur} {spread} rgba(color, opacity)`. `spread` для текстовых теней
игнорируется. Единицы измерения — частью строки (`"0"`, `"2px"`), чтобы
принимать и числа, и `0`.

`shadow.text` применяется к `.widget-label` — это единственное место, где
текстовая тень используется сейчас (`BaseWidget.vue:143`). Распространять ли
её на заголовок и содержимое виджета — решение будущей задачи, здесь
фиксируем текущее поведение.

### 2.4 Допустимые значения `border.style`

`solid` \| `dashed` \| `dotted` \| `double` \| `none`. Значение `none` снимает
рамку, но оставляет `radius` (для скруглённых карточек без обводки) и тени.

### 2.5 Про `appText`

`palette.appText` — **не** настройка цвета текста виджетов. Это токен
уровня приложения, который служит значением по умолчанию для
`contentColor` виджета. Сам цвет текста виджета настраивается в свойствах
виджета и в теме не лежит (кроме заголовка — `widgetTitleColor`, он общий
для всех виджетов и в теме).

## 3. Прозрачность × градиенты

Ползунки прозрачности в настройках дашборда (`DashboardSettingsDialog.vue:203-236`,
поля `widgetBackgroundOpacity` / `widgetHeaderOpacity` / `widgetBorderOpacity`
в `stores/dashboard.js:17-19`) сейчас применяются через `hexToRgba(color, alpha)`
и на градиенте не работают.

**Правило:** множитель из дашборда (0..100 → 0..1) применяется к каждому стопу
градиента и к каждому сплошному цвету одинаково.

```
градиент при 80%  →  linear-gradient(180deg,
                      rgba(28,33,40,0.8) 0%,
                      rgba(22,27,34,0.8) 100%)
```

На прозрачность строки-«сырого CSS» множитель не действует — она не разбирается.
Поведение сплошных цветов не меняется, существующие дашборды работают как
раньше. `alertColor` множителем не затрагивается: алерт должен оставаться
заметным при любой прозрачности.

## 4. Слой применения

Все токены пишутся **на `document.body.style** одним вызовом. Не инлайном на
`.dashboard-grid`, как сейчас (`IndexPage.vue:163-181`).

Причины: единственная точка записи, ноль прокидывания через компоненты,
и — важно — работает для виджетов в портальных drag-диалогах, у которых
сейчас не работает.

| JSON | CSS-переменная | Потребитель |
|---|---|---|
| `palette.appBackground` | `--app-bg` | `.dashboard-grid` |
| `palette.appText` | `--app-text` | дефолт `--widget-content-color` |
| `palette.widgetBackground` | `--widget-bg` | `.widget-container` |
| `palette.widgetHeaderBackground` | `--widget-header-bg` | `.widget-header` |
| `palette.widgetTitleColor` | `--widget-title-color` | `.widget-title` |
| `palette.widgetBorderColor` | `--widget-border-color` | `.widget-container` |
| `palette.alertColor` | `--widget-alert-color` | `.widget-container--alert` |
| `border.width` | `--widget-border-width` | `.widget-container` |
| `border.style` | `--widget-border-style` | `.widget-container` |
| `border.radius` | `--widget-border-radius` | `.widget-container` |
| `shadow.widget` | `--widget-shadow` | `.widget-container` |
| `shadow.text` | `--widget-text-shadow` | `.widget-label` |
| `font.family` | `--app-font-family` | `.dashboard-grid` |
| `font.widgetTitleSize/Weight` | `--widget-title-font` | `.widget-title` |
| `font.widgetContentSize/Weight` | `--widget-content-font` | `.widget-content` |

### 4.1 Фолбэки убираются

`var(--widget-bg, #424242)` и подобные фолбэки — источник бага «тёмный виджет
в светлой теме» для всего, что отрисовано вне области действия инлайн-стилей.
Из `BaseWidget.vue:110-134` и `GridContainerWidget.vue:456-482` они
выбрасываются.

Взамен: в `src/css/app.scss` (сейчас пустой) лежат статические значения по
умолчанию для всех переменных. Каждый стартовый пресет и каждая загруженная
тема определяет токены полностью. Переменная не может оказаться
неопределённой ни при каком сценарии.

### 4.2 Резерв под состояние алерта

Класс заводится сейчас, логика перехода — в будущей задаче:

```css
.widget-container--alert {
  border-color: var(--widget-alert-color);
  box-shadow: 0 0 0 2px var(--widget-alert-color);
}
```

Фон и содержимое при алерте не меняются. Это предварительное решение —
пересмотреть, когда появится сама фича алертов.

## 5. Бэкенд

### 5.1 Таблица

```python
class Theme(Base):
    __tablename__ = "themes"
    id:         Mapped[str]  = mapped_column(String(64), primary_key=True)
    name:       Mapped[str]  = mapped_column(String(128))
    payload:    Mapped[dict]  = mapped_column(JSON)
    created_at: Mapped[int]   = mapped_column(Integer)
    updated_at: Mapped[int]   = mapped_column(Integer)
```

Весь JSON целиком в `payload`, а не расплющенные колонки: экспорт = отдать
`payload` как есть, правка = полный PUT, а расширение набора токенов не
требует миграций. Атрибута `is_dark` нет — см. раздел 1.

`id` берётся из поля `id` темы JSON, приводится к нижнему регистру и
допускает только `[a-z0-9-]`, 1..64 символа. Сравнение регистронезависимое,
чтобы `Midnight` и `midnight` не оказались двумя темами.

### 5.2 Эндпоинты

Базовый путь `/api/v1/themes`, по образцу `api/dashboards.py`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `` | список тем. Отдаёт полные payload — они маленькие, а список нужен пикеру с превью |
| GET | `/{id}` | полный payload |
| POST | `` | создать из присланного JSON. `id` уже существует → 409 |
| PUT | `/{id}` | полная замена payload |
| DELETE | `/{id}` | удалить |
| GET | `/{id}/export` | тот же payload с `Content-Disposition: attachment; filename="{id}.theme.json"` |
| GET | `/schema` | JSON Schema, выведенная из pydantic-модели |

### 5.3 Валидация — строгая

Pydantic-модели зеркалят схему. **Неизвестный ключ → 422 со списком
допустимых.** Для рукописного конфига опечатка в `borderColor`,
молча проигнорированная, обойдётся пользователю дороже всего.

### 5.4 Сидинг

`seed_themes_if_empty(session)` в `services/theme_service.py`, вызов из
`lifespan` (`main.py:23`). Логика: если `count(themes) == 0` — вставить все
JSON из `backend/app/themes/*.json`. Иначе не трогать ничего.

Отдельная функция, а не код внутри `lifespan`, иначе её не покроет фикстура
`client` (`tests/conftest.py:78`).

Класс «встроенная тема» не существует: нет флага `is_builtin`, нет защиты от
удаления и от перезаписи. Темы из репозитория — это стартовый набор, и после
сидинга они принадлежат пользователю целиком. `COPY backend/app /backend/app`
в `deploy/Dockerfile-backend` уже включает каталог, правки Dockerfile не нужны.

### 5.5 Удаление занятой темы

Если на тему ссылается хотя бы один дашборд (`options->>'theme'`) — 409
со списком дашбордов. Молча переназначать чужие дашборды на тему по
умолчанию нельзя.

## 8. Задел под редактор темы

Редактор — следующая задача, здесь только то, что **не даст ему потом
потребовать переделки схемы или слоя применения**.

1. **`GET /api/v1/themes/schema`** отдаёт `ThemePayload.model_json_schema()`.
   Редактор рендерит поля из неё → схема не может разъехаться с валидацией
   бэкенда. Один источник истины вместо дублирования на фронте.
2. **Два режима нормализации.** `strict` — импорт и сохранение, бросает на
   неизвестный ключ. `lenient` — живое редактирование: неизвестный ключ
   игнорирует, битое значение заменяет дефолтом, не падает, пока юзер
   набирает `#1a2`.
3. **`applyTheme(theme)` — чистая функция от объекта темы.** Ни сети, ни
   стора, ни записи в `localStorage`. Обязательное условие: `appliedTheme`
   (закоммиченная) и `draftTheme` (черновик) — **разные объекты**;
   отмена = переприменение закоммиченной.
4. **Поля — плоские листья с типизированными значениями.** Уже так: `Paint`,
   enum `border.style`, px-строки, числа. Контрол выбирается по типу листа:
   `Paint` → пипетка + переключатель градиента, enum → select, px → число
   и юнит.
5. **«Сбросить поле»** не требует поля `extends` в схеме: редактор снимает
   снапшот темы при открытии и восстанавливает лист из него.
6. **Живое превью = сам дашборд под диалогом.** Диалог редактора не должен
   перекрывать сетку. Требование к его вёрстке, не к схеме.
7. `ThemeSelect.vue` вынесен отдельно, чтобы редактор переиспользовал
   список тем.

## 9. Стартовые пресеты

`dark` и `light` переносятся в новый формат. Внешний вид сохраняется
один-в-один — те же цвета, `radius: 4px`, `border: 1px solid`, тени `0` —
чтобы не менять картинку у текущих пользователей. Недостающие токены
заполняются явными значениями, а не захардкоженными фолбэками. Третью тему
с градиентом пока не добавляем: градиенты показываем на этапе редактора.

## 10. Что не входит

- графики и цвета текста содержимого виджетов — свойства виджета
- прозрачность фона и обводки — настройки дашборда
- отступы — настройки дашборда
- изображения
- анимации
- хром диалогов настроек — следует за UI-темой, темами дашборда не красится
- визуальный редактор тем (только задел, раздел 8)
- мультиаренд и квоты — аутентификации в проекте нет вообще

- строгая валидация режет опечатку в ключе с перечислением допустимых
- `GET /export` отдаёт `Content-Disposition` с корректным `filename`
- удаление темы, на которую ссылается дашборд, даёт 409
- удаление незанятой темы проходит

**Frontend** — раннера нет (`frontend/package.json:10` — заглушка),
добавлять vitest не будем: это вне задачи. Чистые функции
`normalizeTheme` / `paintToCss` / `shadowToCss` держатся в
`utils/themes.js` без Vue-зависимостей, чтобы тесты на них можно было
навесить позже одной командой. Проверка — ручной чеклист:

- 2 пресета × (светлый/тёмный/системный хром) — 6 комбинаций
- градиентный заголовок виджета, радиус 12px, `dashed` рамка, обе тени
- портальный drag-диалог с виджетом — цвета темы, а не тёмный фолбэк
- смена темы перерисовывает графики
- импорт/экспорт: скачанный файл грузится обратно без потерь
- удаление занятой темы даёт понятное сообщение

## 12. Риски

- **Строгая валидация + ручные JSON.** Первый же неверный ключ у юзера
  даёт 422. Это осознанный размен: сообщение об ошибке должно перечислять
  допустимые ключи, иначе пользователь не поймёт, что исправлять.
- **Каталог тем в `localStorage` исключён.** Оверлей-заглушка на время
  загрузки — осознанный размен против мгновенного рендера. На локальной
  сети приемлемо.
- **Снятие зависимости от `body--dark`** затрагивает `IndexPage.vue:341` и
  требует ручного прогона по всем Quasar-компонентам, попавшим в зону
  дашборда, — иначе внутри светлой темы останутся тёмные пятна.
- **Хрупкость JSON-схемы.** `version: 1` зафиксирован, но миграций старых
  версий не предусмотрено — при изменении набора токенов потребуется
  либо преобразование в `normalizeTheme`, либо bump версии с конверсией.
